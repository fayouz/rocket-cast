## Avec Docker Compose

::steps{level="3"}

### Démarrer la stack

```bash [Terminal]
docker compose up -d --build
```

Cela lance PostgreSQL, l'API (qui applique les migrations au démarrage), le worker et le front.

### Créer le compte administrateur

Ouvrez http://localhost:3600. Tant qu'aucun compte n'existe, Rocket Cast affiche la page **Configuration initiale** : nom, email et mot de passe (12 caractères minimum) de l'administrateur. La page n'est plus jamais accessible ensuite.

::warning
Tant que le compte n'est pas créé, la première personne qui ouvre l'application peut le créer. Si l'instance est accessible par d'autres avant que vous la configuriez, définissez `SETUP_TOKEN` : la page demandera ce jeton.
::

Vous pouvez aussi créer l'administrateur en ligne de commande :

```bash [Terminal]
docker compose exec api php bin/console app:user:create admin@exemple.com 'un-mot-de-passe-long' --admin
```

### Installer les écrans

Déclarez vos [sources](/display/sources), composez une [playlist](/display/playlists), puis [appairez les écrans](/display/screens) : `/pair` sur l'écran, **Écrans → Appairer un écran** dans Rocket Cast.

::

| Adresse | Contenu |
|---|---|
| http://localhost:3600 | Application Rocket Cast |
| http://localhost:8600/api/docs | Documentation OpenAPI de l'API |

## Réseau

L'API doit joindre les sources (Rocket PMS, Rocket Place, API JSON). Les écrans n'ont besoin que du front et de l'API de Rocket Cast, et d'Open-Meteo (`api.open-meteo.com`) pour les panneaux météo ; les images sont chargées par l'écran depuis leur adresse.

## Images Docker

La CI publie deux images sur GitHub Container Registry, pour `main`, `develop` et les tags `vX.Y.Z` :

- `ghcr.io/fayouz/rocket-cast-api` : API, et aussi le worker, avec la commande `php bin/console messenger:consume async scheduler_default` ;
- `ghcr.io/fayouz/rocket-cast-front` : front Nuxt.

L'API et le worker partagent la base de données ; le worker vérifie les sources toutes les 5 minutes.

## Configuration

### API

| Variable | Rôle | Défaut |
|---|---|---|
| `DATABASE_URL` | Connexion PostgreSQL | — |
| `APP_SECRET` | Secret Symfony | — |
| `JWT_PASSPHRASE` | Passphrase des clés JWT (`config/jwt/`, à monter en volume) | — |
| `MESSENGER_TRANSPORT_DSN` | File des tâches de fond | `doctrine://default` |
| `DATA_DIR` | Données de l'application (vérifiées par le tableau de bord) | `var/data` |
| `FRONTEND_URL` | Adresse publique du front : liens d'écran `/s/<jeton>` renvoyés par l'API | `http://localhost:3600` |
| `ROCKET_SECRETS_KEY` | Clé maîtresse du coffre des secrets de rocket-core, qui garde les identifiants des sources (base64 de 32 octets, `php bin/console rocket:secrets:generate-key`). La perdre rend les identifiants illisibles. | — |
| `CAST_LEGACY_SECRETS_KEY` | Transition : ancienne valeur (hexadécimale) de `ROCKET_SECRETS_KEY`, le temps de `php bin/console app:secrets:migrate`. | — |
| `CAST_SOURCE_TIMEOUT` | Délai des requêtes aux sources, en secondes | `5` |
| `CAST_CLOUD_URL` | Origine de Rocket Cloud acceptée par les panneaux image, en plus des adresses `https://` (ex. `http://localhost:3200`) | — |
| `SECRETS_ENCRYPTION_KEY` | Clé de chiffrement des secrets en base (mot de passe de l'annuaire, secrets SSO). Vide : dérivée de `APP_SECRET`. La changer oblige à ressaisir les mots de passe. | — |
| `CORS_ALLOW_ORIGIN` | Origines autorisées à appeler l'API depuis un navigateur (regex) | localhost |
| `SETUP_TOKEN` | Jeton demandé par la page de configuration initiale | — |
| `UPDATE_REPOSITORY` | Dépôt GitHub dont les nouvelles versions sont signalées. Voir [Mises à jour](/administration/updates). | `fayouz/rocket-cast` |
| `UPDATER_TOKEN` | Active la mise à jour en un clic, avec le service `updater` (profil `updater`) | — |
| `RUN_MIGRATIONS` | `1` pour appliquer les migrations au démarrage du conteneur | `0` |

Les variables LDAP sont décrites dans [Utilisateurs et LDAP](/administration/users-ldap).

### Autonome ou dans la suite Rocket

Par défaut, Rocket Cast est **autonome** : il gère ses comptes (locaux, LDAP, fournisseurs OpenID Connect). Dans la **suite** Rocket, la connexion passe par Rocket Auth, qui gère aussi les utilisateurs, les groupes et l'annuaire :

| Variable | Rôle | Défaut |
|---|---|---|
| `ROCKET_AUTH_URL` | Adresse publique de Rocket Auth. Renseignée : mode suite. | — |
| `ROCKET_AUTH_INTERNAL_URL` | Adresse de Rocket Auth vue par l'API (ex. `http://auth-api` dans Docker) | l'adresse publique |
| `ROCKET_AUTH_CLIENT_ID`, `ROCKET_AUTH_CLIENT_SECRET` | Client OpenID Connect de Rocket Cast, déclaré dans Rocket Auth | `rocket-cast` |
| `ROCKET_AUTH_ADMIN_GROUP` | Groupe de Rocket Auth dont les membres administrent Rocket Cast | `rocket-admins` |
| `ROCKET_LOCAL_LOGIN` | `1` : accès de secours par mot de passe local | `0` |
| `ROCKET_INTERNAL_URL` | Adresse de Rocket Cast vue par le serveur de Rocket Auth (ex. `http://cast-api` dans Docker) : Rocket Auth y envoie les déconnexions (back-channel logout) | `ROCKET_PUBLIC_URL`, sinon `FRONTEND_URL` |

En mode suite, se déconnecter de Rocket Auth, ou y être désactivé ou supprimé, ferme les sessions de l'utilisateur dans Rocket Cast : Rocket Cast déclare à Rocket Auth son adresse de déconnexion (`<ROCKET_INTERNAL_URL>/api/auth/oidc/backchannel-logout`) à la première connexion et avec `php bin/console rocket:suite:sync`.

Voir le [README de rocket-core](https://github.com/fayouz/rocket-core#modes-autonome-et-suite).

### Tâches planifiées

Le worker (`messenger:consume async scheduler_default`) lance lui-même :

- toutes les 5 minutes, la lecture des sources actives (ce qui rafraîchit aussi leurs données), et la vérification de l'annuaire et des fournisseurs SSO.

Avec LDAP, planifiez aussi la synchronisation de l'annuaire :

```bash [crontab]
*/30 * * * *  docker compose exec -T api php bin/console app:ldap:sync
```

### Front

| Variable | Rôle |
|---|---|
| `NUXT_PUBLIC_API_BASE` | URL de l'API vue par le navigateur. **Vide** : le front relaie `/api` vers l'API (une seule URL publique, pas de CORS). |
| `NUXT_API_INTERNAL_BASE` | URL de l'API vue par le serveur du front, ex. `http://api:80` |

::warning
En production, changez `APP_SECRET` et `JWT_PASSPHRASE`, montez les clés JWT dans un volume persistant et servez le front et l'API en **HTTPS**.
::
