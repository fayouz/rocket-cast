Rocket Cast est la brique d'**affichage dynamique** (digital signage) du Middleware Rocket. Un écran, c'est un navigateur en plein écran ouvert sur un lien secret `/s/<jeton>` : TV connectée, clé HDMI, tablette, mini-PC… Pas de boîtier propriétaire.

## Architecture

| Élément | Technologie | Rôle |
|---|---|---|
| API | Symfony 8, API Platform, PostgreSQL | Comptes, écrans, playlists, sources, API publique des écrans |
| Worker | Symfony Messenger et Scheduler | Vérification des sources et des services toutes les 5 minutes |
| Front | Nuxt 4, Nuxt UI 4 | Administration, page kiosque `/s/<jeton>`, appairage `/pair` |
| Documentation | Nuxt Content | Ce site, et le changelog |

Rocket Cast partage son socle (comptes, LDAP, SSO, applications, tableau de bord, mises à jour) avec les autres briques Rocket : [rocket-core](https://github.com/fayouz/rocket-core).

## Comment un écran affiche sa playlist

1. La page `/s/<jeton>` demande `GET /api/public/screens/<jeton>` : l'API renvoie les panneaux **actifs maintenant** dans le fuseau de l'écran, les panneaux « source » remplis avec les données de leur source, et `reloadAt`, l'heure à laquelle redemander (prochain changement de programmation, prochaine arrivée d'un voyageur, 15 minutes au plus).
2. L'écran joue les panneaux en boucle, chacun pendant sa durée, et redemande la playlist chaque minute (c'est aussi son signal de présence : « en ligne » dans l'administration).
3. Les sources sont lues par l'API, jamais par l'écran, et gardées en cache selon leur intervalle de rafraîchissement ; seule la météo (Open-Meteo, sans clé) est lue par le navigateur.
4. Si l'API ou le réseau tombe, l'écran rejoue le dernier contenu reçu (`localStorage`) et affiche un discret « Hors ligne ».

## Sécurité

- Le jeton d'un écran fait 256 bits ; seule son empreinte SHA-256 est stockée. Le lien n'est affiché qu'une fois (création, nouveau lien, appairage) et se révoque en un clic.
- L'API publique est limitée par adresse IP (120 requêtes par minute, 10 jetons invalides par minute), jamais mise en cache (`Cache-Control: no-store`) ni indexée (`X-Robots-Tag: noindex`).
- Les identifiants des sources sont gardés dans le coffre des secrets de rocket-core (chiffrés en base, `ROCKET_SECRETS_KEY`) et ne sont jamais renvoyés par l'API.
